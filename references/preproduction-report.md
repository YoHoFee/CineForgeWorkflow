# 合并制作设计报告

每个媒体批次都必须在任何付费生产前生成一份报告。该报告是该批次唯一的确认依据；
图片批次和视频批次分别确认，图片批次的确认不授权视频。

## 必备章节

1. **需求与路由摘要**：请求详细程度、用户明确意图、已解决/仍缺失的输入、复用
   内容和本批次实际执行的 Skill。非本批次阶段明确标记为 `skip`。
2. **任务契约**：标题、格式、时长、画幅、平台、音频和排除项。
3. **创作方向**：前提、基调、视觉风格、结尾和风险说明。
4. **故事包**：人物关系、场次顺序、剧本、镜头表和时间安排。
5. **资产决策**：逐个角色、场景、关键帧和必要道具标记 `reuse`、`generate`、
   `variant` 或 `blocked`，并记录已保存资产 ID、目标尺寸、实际尺寸、自然尺寸、
   比例、验收状态和计划使用的节点。
6. **角色设定图**：每个新角色一张符合下游画幅的统一角色设定图，16:9 视频优先
   使用 16:9，遵循四区模板。
7. **场景设定图**：每个新场景一张符合下游画幅的无人物场景设定图，16:9 视频优先
   使用 16:9，遵循多角度分区模板。
8. **提示词与参考图**：完整的图片/视频提示词及有序参考图绑定关系。
9. **视频提示词交接**：来源 Skill、提示词文件路径、哈希、镜头数量、每张参考图的
   顺序/用途/控制范围/不得控制范围，以及交接校验状态。
10. **片段链计划**：目标总时长、模型单次上限、片段数量、每段时长、首帧来源、
    尾帧接力方式和最终拼接方式；不超上限时明确记录为单片段。
11. **生产参数**：模型、图片质量、图片尺寸、视频分辨率、数量、时长、音频、
   水印和重试策略。
12. **成本边界与确认**：预计任务数、报告指纹、所有付费媒体的确认范围和唯一确认
   短语。

## 确认规则

图片任务可以先准备，但必须在当前批次确认后执行。确认绑定报告指纹，并授权报告中
列出的图片、视频、配音或音乐 targets，例如：

```text
CONFIRM PREPRODUCTION PACKAGE <report-id> <fingerprint>
```

确认只覆盖报告中列出的目标 targets。任何创意或技术参数变化，或任何图片验收失败，
都必须建立新的报告状态并重新确认。静态图片尚未验收时，不得建立视频确认报告。

`reportHash` 使用报告规范化文本的 SHA-256：先统一换行，并把报告中的
`reportHash: sha256:<64位十六进制>` 与唯一确认短语中的
`CONFIRM PREPRODUCTION PACKAGE <package-id> sha256:<64位十六进制>` 的指纹都替换为
`sha256:<REPORT_HASH>` 后再计算。最终两处必须写入同一个实际 SHA-256；确认或生产阶段
必须重新计算并匹配，不能只检查报告里是否出现某个字符串。

## 复用规则

资产检索必须在报告定稿前完成。已保存且在身份、风格和所需视角上匹配的成功资产
应直接复用，不得把复用资产列为新的生成目标。

报告只覆盖当前批次实际需要的范围。若本轮只是补角色设定或补视频提示词，不得
为了满足固定章节而虚构新的故事、场景或媒体生产目标；未执行阶段应保留可追踪的
`skip` 路由记录。

视频提示词交接状态不是参考图数量的替代物。只有
`videoPromptHandoff.status=validated` 才能把报告提交到视频确认闸口。

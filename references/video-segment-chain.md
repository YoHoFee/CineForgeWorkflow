# 视频片段链交接契约

本契约属于 `$short-video-workflow` 编排层，用于处理目标时长超过视频模型单次生成
上限的连续视频。它不修改第三方视频模型 Skill，也不把多个独立片段伪装成一个任务。

## 模型上限

默认使用项目 `production_profile` 中的目标模型能力档案。下表只是规划参考，不是渠道
实际合法参数的权威来源；提交前必须读取当前 adapter/渠道返回的真实约束。

| 模型 | 单次最长时长 |
| --- | ---: |
| `minimax-h3` / H3 | 15 秒 |
| `seedance-2.0` | 30 秒 |
| `seedance-2.5` | 30 秒 |

如果项目能力档案提供了更严格的上限，以项目档案为准。不能只把超长秒数写进提示词，
再让下游 adapter 自行截断。

## 拆分规则

1. 先按剧情和导演意图定义完整镜头，再核对当前模型和渠道真实接受的时长选项；
   能力档案中的最大时长不一定等于 adapter 的合法枚举。
2. 一个完整镜头能放入单次合法时长时，就用一个片段；可缩短镜头或选择更短合法时长，
   不为凑上限拆镜，也不为凑满时长添加无叙事作用的动作。
3. 只有完整镜头确实超过单次上限、且无法通过重排/缩短解决时才拆分。优先在自然动作
   落点、状态落点或明确剪辑点拆分。
4. 若同一个连续镜头不得不跨段，保留起止动作和连续性状态；不能静默截断动作，也不能
   把后段错误地当作独立文生视频。
5. 每段时长必须符合当前模型和渠道约束；当整体目标时长有弹性时，完整叙事和镜头优先
   于凑齐预估秒数。

## 首尾帧接力

被拆开的同一连续镜头必须形成单向链：

```text
原始首帧
  → 片段 1
  → 片段 1 的真实视频尾帧
  → 片段 2
  → 片段 2 的真实视频尾帧
  → 片段 3
  → ...
```

具体规则：

- 片段 1 使用原始冻结关键帧或本镜声明的真实起始参考。
- 片段 2 及之后必须使用上一片段生成结果中提取的**真实尾帧**作为首帧参考。
- 真实尾帧必须建立为可读取的项目媒体或 Canvas 图片节点，并记录节点 ID、尺寸、
  画幅和来源视频 ID。
- 不能用文字描述、计划中的关键帧、上一片段的提示词或截图占位来冒充真实尾帧。
- 后续片段可以继续绑定角色设定图、场景图等稳定参考，但上一片段真实尾帧负责
  当前可见起始状态。
- 同一链必须串行生成。上一片段没有通过视频验收并提取尾帧时，不得提交下一片段。
- 任何片段参数、参考集合、模型、时长或起始尾帧发生变化，都必须使后续片段和
  原确认一起失效，重新建立片段链。
- 若两段之间本来就是明确切镜，而非同一镜头延续，不强制绑定前段尾帧；使用新镜头
  自己的起始构图和已确认的角色/场景参考即可。

## 片段记录

每个片段至少记录：

```json
{
  "segmentId": "SEG-001",
  "sourceShotId": "MOTION-001",
  "index": 1,
  "durationSeconds": 15,
  "startFrameSource": "frozen-keyframe",
  "startFrameRef": "keyframe-001",
  "outputVideoRef": null,
  "tailFrameRef": null,
  "status": "planned"
}
```

片段 2 的最小记录必须体现：

```json
{
  "index": 2,
  "startFrameSource": "actual-tail-frame",
  "startFrameRef": "tail-SEG-001",
  "previousSegmentId": "SEG-001"
}
```

允许的片段状态为：

```text
planned
awaiting_previous_output
ready
in_production
generated
tail_frame_extracted
blocked
completed
```

## 生产与拼接

- 片段 1 生成并验收后，提取真实尾帧，再解锁片段 2。
- 片段 2 及之后只在前一片段拥有真实视频和真实尾帧时提交。
- 所有片段完成后，交给 `$short-drama-edit` 按片段索引拼接。
- 拼接阶段要检查画幅、帧率、音频连续性、尾首画面重复帧和总时长。
- 片段链未完成时，不能把已完成的第一片段登记为整段最终成片。
